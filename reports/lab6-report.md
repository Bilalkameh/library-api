## 4. Coupling analysis

Ce is the number of **distinct explicit imported types** in each service. The count includes project types, JDK types, framework types, annotation types, enums, and interfaces. Ca counts distinct **production Java types** explicitly importing that service, with tests excluded. Repeated uses do not increase either count. These services and their importers use explicit imports; no wildcard expansion is needed for the measured edges.

This is the handout's import-based proxy, not a full semantic CBO analysis: implicit `java.lang` references, unimported same-package or fully qualified references, runtime implementations, and transitive dependencies are not counted. Chapter 6 p. 66 defines instability at package scope; applying its ratio to classes here does not make the two scopes equivalent.

### Why the selected finding is IMPORTANT

SpotBugs reported `EQ_DOESNT_OVERRIDE_EQUALS` on `ApiError`, priority **2 (normal)**, rank **17**. Its added `timestamp` and `errors` fields were outside the superclass state. The new tests demonstrate that errors with different timestamps or different field-validation maps compared equal. That loses distinctions in public value comparisons, so the finding is treated as IMPORTANT for this lab. No HTTP failure or existing production hash-collection use was observed.

The rule warns that directly overriding a subclass's equality can break symmetry when the superclass uses `instanceof`. [SpotBugs pattern description](https://spotbugs.readthedocs.io/en/stable/bugDescriptions.html#eq-class-doesn-t-override-equals-in-superclass-eq-doesnt-override-equals). The installed Spring **6.2.19** implementation was checked: `ProblemDetail.equals` accepts other ProblemDetail instances and compares its extension-property map, and `hashCode` includes that same map. [ProblemDetail 6.2.19 source](https://raw.githubusercontent.com/spring-projects/spring-framework/v6.2.19/spring-web/src/main/java/org/springframework/http/ProblemDetail.java).

### Correction and verification

`ApiError` now stores `timestamp` and `errors` in that inherited map and has no additional instance fields. It retains its typed, documented getters and defensively copies validation maps. A small helper tolerates `setProperties(null)`. The two names are reserved typed extension keys: generic property writes must use an `Instant` for timestamp and a `Map<String, String>` for errors. Arbitrary other extension keys remain supported.

The inherited `equals` and `hashCode` implementations remain unchanged and see the complete value, including when a plain ProblemDetail has matching extensions. This preserves superclass/subclass symmetry without adding a special-case equality algorithm. Jackson ignores these two keys in the map's flattened serialization because the typed getters already emit them; unrelated extension keys still appear at the top level. The unchecked-cast compiler annotation documents type erasure at the typed map getter; it does not suppress a PMD or SpotBugs finding.

The initial fourteen-case regression run had four assertion failures before production edits. Two directly exposed missing timestamp/validation distinctions. The other two specified matching superclass extension state and inherited property replacement for the chosen design; they did not demonstrate an existing asymmetric equality implementation. The original inherited comparison was symmetric but omitted the subclass fields.

After correction, all fourteen cases pass. They cover equality differences, equal-value hashes and set deduplication, superclass/subclass comparisons in both directions, inherited problem fields, defensive copying, property-map replacement/clearing, and wire-format compatibility. JSON is parsed with strict duplicate-key detection, so repeated timestamp/errors keys cannot be hidden by conversion to a JSON tree. The existing HTTP and OpenAPI tests also pass unchanged, protecting status codes, error fields, schemas, and all fourteen operations.

A final test review corrected two null/unrelated-object assertions to invoke `ApiError.equals` directly, followed by the final full test/analyzer run. No production change followed the passing clean build. PMD/SpotBugs reruns used the same configuration and current compiled bytecode; the selected occurrence disappeared and no new finding appeared. The improvement is corrected error-value state, not a reduction in service complexity or coupling.
